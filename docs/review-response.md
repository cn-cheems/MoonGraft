# MoonGraft 复审补充说明（供修改报名材料使用）

感谢评审指出定位与可行性说明不充分的问题。原申报中“通用项目模板持续升级工具”
的表述过宽，现收敛为：**面向已渲染项目模板的可审阅升级引擎与 MoonBit 库**。

首期输入是旧模板基线、当前项目、新模板结果三份文件树。模板渲染由已有生成器或
明确适配流程负责；首期不承诺通用模板语法、框架语义迁移或所有生成器兼容。
其独立价值是将文件比较连接为可连续采用的流程：版本基线 → 目录级规划 → 显式协调
→ 过期检查与保守刷新 → 策略门禁 → 候选导出、验证及回退。

实现路径：不可变文件树保存原字节；目录规则区分新增、删除与本地定制；适用的文本
执行有资源上限的保守合并，二进制或重叠修改要求人工决策。应用前验证整个当前快照，
策略通过后才创建新候选目录。新基线保持为模板结果，避免把业务修改误作模板原貌。

已补充完整公开模板案例：`mizchi/moonbit-template` 的真实提交 `4733b6f` 与 `580024a`，
分别保留全部 21 个文件及 Git blob 标识。案例明确披露旧配置迁移、依赖固定和已知链接
物化三项适配；在旧版本上添加业务函数、业务测试及本地 README 说明，再合入真实上游
变更。对整个 23 文件结果、业务内容、新基线及回退做独立断言，执行升级前后项目测试，
以及新版 JavaScript 构建和程序运行。上游新版属性测试执行 100 组样例。

稳定性证据包含核心边界测试、确定性与往返属性、异常拒绝、跨系统实际运行和完整案例。
历史模板仍产生弃用警告，本案例只证明其 JavaScript 目标；它不能代表所有模板兼容，
也不能保证任意合并结果的业务语义。目标项目自己的构建和测试仍是采用前必要验证。

仓库：[cn-cheems/MoonGraft](https://github.com/cn-cheems/MoonGraft)。
[完整来源、适配、限制与复现步骤](../integration/README.md)。
复现命令：`moon update` 后运行 `moon run --deny-warn integration/template_case`。
跨系统 CI 会上传绑定提交版本的案例结果；请以相应提交的实际完成状态为准。
