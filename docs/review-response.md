# MoonGraft 复审补充说明（供修改报名材料使用）

**项目定位**　MoonGraft 是用 MoonBit 实现的通用项目模板管理与持续升级工具，面向需要维护多个服务、应用或开源仓库的团队。通用性体现在按版本管理不同语言项目的文件树。升级流程提供独立候选目录，维护者可以协调冲突、运行项目测试、核验候选，再记录采用的模板版本。

**已实现**　首版打通本地 Git 模板的生命周期：固定提交及子目录 → 创建项目并保存来源 → 检查指定新版本 → 基于旧模板、当前项目和新模板规划升级 → 协调冲突并导出 → 验收后推进来源记录 → 继续升级。现有生成器的渲染结果也可通过目录工作流接入。 [命令与示例](../README.md#从-git-模板创建项目)

**使用场景**　平台团队从固定模板创建服务，上游修复 CI 配置后生成候选，在保留服务自定义检查的前提下验证并采用。开源维护者从模板创建库，模板与本地同时修改 README 时显式协调，再运行发布前测试。已有脚手架的团队分别渲染新旧版本，导入现有项目生成候选，用业务回归测试确认可采用后保留新基线。

**拟实现及验收条件**

1. **参数化渲染与变量记录。** 固定生成器版本和非敏感变量，使用同一组参数重建指定版本。首个适配器拟接入 `moon-new`，以同一模板生成两个参数不同的项目并分别连续升级，验证文件内容与路径。 [moon-new 文档](https://mooncakes.io/docs/moonbit-community/moon-new)
2. **来源绑定与版本发现。** 为既有项目记录其确切模板版本，提供显式 Git 来源获取和候选版本检查。用既有项目和三次上游提交验证绑定、发现、固定目标和连续升级。
3. **批量升级与 CI 集成。** 为多个项目独立输出候选、状态及冲突清单。使用两个派生项目验证其中一个发生冲突时，另一个仍可完成升级，并核验各自的基线。

| 能力 | Copier | Cruft | MoonGraft 首版 |
| --- | --- | --- | --- |
| 创建及变量 | Jinja 渲染、回答文件 | Cookiecutter 渲染、记录变量 | 固定本地 Git 提交和子目录，生成完整项目 |
| 来源及检查 | 记录来源与版本，可检查升级 | `.cruft.json`、`link`、`check`、`diff` | 独立 JSON 记录，比较指定提交，验收后推进基线 |
| 升级及冲突 | 更新项目，可用行内标记或 `.rej` | 更新项目，冲突可生成 `.rej` | 保存升级计划、显式决策和可选门禁，导出独立候选，按实际采用内容验收 |

Copier 与 Cruft 是工作流和功能边界的参考，MoonGraft 使用自己的 MoonBit 实现。 [Copier 更新文档](https://copier.readthedocs.io/en/stable/updating/) · [Cruft 文档](https://cruft.github.io/cruft/)

**稳定性与复现**　直接读取固定 Git 提交中的文件字节。三方计划应用前核验当前快照，冲突未解决时拒绝导出，验收时核验候选与目标模板。运行 `moon run --deny-warn scripts/git-lifecycle.mbtx` 可验证三次提交下的项目创建、业务修改保留、验收拒绝与两轮升级。另有真实公开模板两版本案例，记录了旧配置适配、业务测试和 JavaScript 构建执行。 [验收说明](acceptance.md) · [真实模板案例](../integration/README.md) · [GitHub CI](https://github.com/cn-cheems/MoonGraft/actions/workflows/ci.yml)
